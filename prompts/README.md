# Промпты: как добавлять и улучшать

Код менять не нужно: промпт = папка с `.md`-файлами. Файлы читаются на каждый запрос, перезапуск сервиса не нужен.

| Что нужно | Вид | Папка | Как создать |
|---|---|---|---|
| Статус сотрудника для нового адресата (руководство, РП, команда, инвесторы) | `audience` | `prompts/<имя>/` | `new audience <имя>` |
| Разбор встречи нового типа (ретро, планирование) | `meeting` | `prompts/meetings/<имя>/` | `new meeting <ключ> --title "Название"` |
| Сводка по периоду в Excel | `digest` | `prompts/digests/<имя>/` | `new digest <имя>` |
| Разбор фото | `image` | `prompts/images/<имя>/` | `new image <имя>` |
| Служебные (разметка говорящих) | - | `prompts/_tasks/` | трогать не нужно |

## Порядок работы
1. **Создать** из шаблона `prompts/_templates/<вид>/` (или `--from существующий`, чтобы править рабочий вариант):
   `python scripts/prompt_studio.py new meeting retro --title "Ретроспектива"`.
   Для `meeting` тип встречи сам регистрируется в `config/meeting_kinds.yaml`.
2. **Отредактировать** файлы в редакторе. Заготовки в угловых скобках `<КОГО: ...>` нужно заменить.
3. **Проверить**: `python scripts/prompt_studio.py check` (пустые файлы, опечатки в метках, забытые заготовки).
   `preview meeting retro` показывает итоговый запрос.
4. **Сравнить** версии на настоящей встрече: ноутбук `notebooks/pipeline_manual_test.ipynb`, часть C «Prompt Studio»
   (результаты рядом, время, в Postgres ничего не пишется).
5. **Применить**: у типа встречи имя папки = ключ типа (или `prompt:` в `config/meeting_kinds.yaml`); аудитория передаётся
   как `audience` в API; сводка - `profile` в `POST /assistant/digests`; фото - `prompt_name`.

## Править и удалять
- В ноутбуке (часть C) есть форма: вкладки с файлами, «Сохранить», «Проверить», «Пробный запуск», «Создать», «Удалить».
- Каждое сохранение кладёт прежний текст в `prompts/.history/`; в форме его можно вернуть кнопкой «Откатить».
- Удаление не стирает файлы, а переносит папку в `prompts/.trash/` (вернуть: «Вернуть» или `lab.undelete(...)`).
  Аудиторию по умолчанию (`ASSISTANT_DEFAULT_AUDIENCE`) удалить нельзя. Разбор встречи, привязанный к типу, удаляется только вместе с типом
  в `config/meeting_kinds.yaml`; встречи этого типа в базе останутся, но разбор по типу для них не сработает, пока тип не вернётся.
- Обе папки в `.gitignore`: это локальные копии, git-историю они не заменяют.

## Метки в файлах
- `meeting`, `digest` (`user.md`): `{transcript} {date} {kind} {kind_title} {file} {tags} {participants}`
- `image` (`user.md`): `{file} {count} {date} {tags}`
- `audience` (`person.md`, синтаксис `${...}`): `${date} ${project_id} ${full_name} ${previous_status} ${examples} ${utterance}`;
  `audience.yaml`: `{date} {project} {index} {full_name} {text}`

## Советы для модели 4B
- Покажите формат ответа готовым шаблоном, а не описанием.
- Запреты конкретные и дословные («не пиши "не указано"»); появилась плохая фраза - добавьте её в запрет.
- Одна задача на промпт; короткий `system.md` (до ~1500 символов).
- Хороший ответ в `examples.md` сильнее абзаца правил.
- Меняйте одно за раз, сравнивайте со старой версией (оставляйте её как `имя_v1`).
