# Промпты разбора встреч по типам

Одна папка = один промпт. Имя папки берётся из `prompt:` в `config/meeting_kinds.yaml` (по умолчанию совпадает с ключом типа).

    prompts/meetings/<тип>/system.md   роль и правила (как писать, чего не делать)
    prompts/meetings/<тип>/user.md     запрос; сюда подставляется встреча

Что подставляется в `user.md` (пишется в фигурных скобках):

| Метка | Значение |
|---|---|
| `{transcript}` | текст встречи (обязательна; нет метки — текст допишется в конец) |
| `{date}` | дата встречи, YYYY-MM-DD |
| `{kind}`, `{kind_title}` | тип встречи: ключ и название |
| `{file}` | имя аудиофайла |
| `{tags}` | теги через запятую |
| `{participants}` | все участники из config/team.yaml |

Вызов: `POST /assistant/runs/{id}/analyze` (промпт берётся по типу встречи) или `{"prompt": "<папка>"}` явно.
Результат сохраняется в таблицу `analyses` и виден в `GET /assistant/runs/{id}`. Файлы читаются на каждый запрос,
перезапуск сервиса не нужен.

Файлы ниже — стартовые шаблоны. Перепишите под себя; чем конкретнее формат вывода и запреты, тем стабильнее
отвечает маленькая модель.
